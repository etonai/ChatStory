## Setting up prompts so that ChatGPT responds with both story information and meta information.

Example:

Day 1 Beat 0

Relationship Values:
Drake -> Morgan STP 5.2

"Hi there"

Drake pulls up a chair


In that example, the Relationship Values are not part of the story, they are more meta information.
The Day / Beat can kind of be thought of as both.

The Canon document probably doesn't need the intermediate relationship values. The beats may or may not be useful.
I lean towards the beats being kept - they can be edited out of the canon document later.

additionally, the canon document may want to keep track of all of the characters in the scenes.

That way, a system can scan a canon document's header and find out who is in the document, without searching through the entire document.

## Canon document highlights

## Automatic Canon Tracking - IMPLEMENTED

Require that all stories incorporate tracking "beats"

Define a beat as something like: One piece of the story
Basically, each ChatGPT prompt will generate 1 story beat. That is the unit of measurement of a story.
Sometimes we need to rewrite a beat before we move on to the next beat.

Instead of "Assistant Response", that window will be "Current beat ###" where ### is the number of the current beat, if any

In the first two lines of any ChatGPT response, the STORY WORKSTATION will look for <Beat #>
If there is no <Beat #> somewhere, then it isn't a beat, and it will not change the Current beat text.

If the # of the new beat is the same as the current beat, it just overwrites the current beat
If the # of the new beat is a new beat #, then it adds the "current beat" to the canon (and also automatically updates the temp canon file with it)

Additionally, when the user Saves Canon, if the current beat has not been saved to canon already, the system will ask if the user wants to save the beat to canon before saving the canon file.
